## Overview

### Overview

 Your game now uses Discord Social SDK for social features, so the next step is telling players what changed. This toolkit gives launch guidance, communication practices, FAQ-oriented messaging, and brand-use constraints so you can explain the integration clearly and follow Discord brand rules. Marketing the integration to players remains your responsibility and choice. Do not imply a Discord partnership, sponsorship, or endorsement unless Discord has given prior written approval for that specific statement.

### Announcement Goals And Messaging

 Announcements about **Discord Social SDK** features should accomplish two things:
- **For Players:** Explain that linking a Discord account makes playing with friends simpler.
- **For Developer:** Increase durable social activity among players.
 Player messaging for Discord Social SDK should differ from developer-facing positioning. The messages below can be adapted for announcement materials. The guidance emphasizes features that motivate Discord account linking, because linking is the key step for players and developers to get the main integration benefits. [Learn more about the impact of account linking](https://discord.com/developers/social-sdk).

 When an announcement covers Discord Social SDK features that do not depend on account linking, this guidance and the brand guidelines are still generally applicable.

### A Note on the Product Name

 The formal product name is "Discord Social SDK". For player announcements, Discord recommends simpler, more conversational wording, and most player-facing copy does not need to include the full product name. Use the guidance below for messaging that tends to work well with players. If the full "Discord Social SDK" name is used, subsequent mentions in the same announcement may shorten it to the "SDK".

### Key Message to Players

 Connect your Discord account to make playing with friends easier.

### Key Benefits to Players

- **Find your friends**
  - Link your Discord account so you can see friends who are playing and join them more easily. Invite friends from inside the game, including friends who are currently offline.

- **Stay connected**
  - Continue conversations by syncing messages and friend lists with Discord.

### Detailed Feature Descriptions

 Use this chart when announcement copy needs to call out individual features and player benefits. Players usually do not need the exact "Feature Name", but the descriptions and example use cases can help explain value.
| Feature Name | Short Description | Use Cases |
| --- | --- | --- |
| **Rich Presence** | Displays on Discord the games that players are currently in. | Seeing friends' in-game activity so you can tell whether they may want to play together; joining from a friend's profile, similar to game invites. |
| **Unified Friends List** | Lets players open their Discord friends list inside the game, including friend tiers. | Sending game invites to friends from within the game; seeing which friends are playing and which online friends might join; avoiding the need to rebuild a social friends list in each new game. |
| **Deeplink Game Invites** | Lets users send invites that deep-link into particular game instances or game areas. | Inviting users into specific game instances or challenges. |
| **Flexible Account Requirements** | Users may link a Discord account for deeper features such as Unified Friends List and Rich Presence, while still being able to use in-game social features without linking by using a "provisional account." | Account linking: Discord-based automatic sign-in, or connecting a Discord account with a game account, enabling the full Discord integration. Provisional accounts: Provisional accounts allow Discord voice and text chat in connected games without first creating a Discord account. |
| **Cross-Platform Messaging** | Enables smooth communication in-game and through Discord, including for players without a Discord account. | DMing friends while they are in-game or outside the game; receiving messages while not playing; in-game text chat for guilds, matches, lobbies, and similar spaces. |
| **Linked Channels** | Lets players connect an in-game group chat to Discord channels, creating persistent group chat spaces. | Mirroring in-game guild or group chat into the guild's or group's Discord server; reducing isolation when some members are online in-game and others are active elsewhere. |
| **Discord Voice Chat** | Adds Discord-powered high quality voice chat directly in the game. | In-game voice chat for guilds, matches, lobbies, and similar group contexts. |

### Integration Announcement Plan Recommendations

 The following channels are recommended for announcing a Discord Social SDK integration to players. Use additional channels as needed for the audiences your players actually follow.
- **In-Game Messaging or Reward (Best)**
  - Use a pop-up, banner, or CTA to announce the update, ask players to link a Discord account, and optionally attach a reward.

- **Announcement Video (Best)**
  - Demonstrate the integration and its benefits with video.

- **Individual Blog Post**
  - Publish a blog post with a fuller explanation of the integration.

- **Patch Notes**
  - Treat the Discord integration details and images as a major update in patch notes.

- **Social Media**
  - Announce through other social channels where players follow updates.

- **Discord Server Announcement**
  - Post in your main Discord announcements channel so the community knows about the update. Add a dedicated discussion area for feedback.

- **Creator Partnership**
  - Work with a creator who can show the integration to their audience.

- **Paid Media**
  - Use paid advertising to prompt Discord account linking.

- **Press**
  - Share the integration story with relevant press. For press questions, include [press@discord.com](mailto:press@discord.com).

- **Support Ticket Setup**
  - Add a support ticket category for related player issues, for example a "Discord account linking" category.

## Overview

### Overview

 Discord Social SDK supplies client-side features for adding Discord social behavior to a game. When a game backend exists, prefer Discord's HTTP APIs for server-side work whenever possible.

### Prerequisites

 Before starting, confirm that you have:
- A Discord application in the Developer Portal
- Access to the bot token for your application
- Required OAuth2 scopes configured

---

### Authentication Types

### Bot Token Authentication

 For server-to-server communication:

```
curl -X GET https://discord.com/api/v10/users/@me \
  -H "Authorization: Bot YOUR_BOT_TOKEN"

```

 In the Authorization header, always put `Bot ` before the bot token.

### Bearer Token Authentication

 For authenticated user actions:

```
curl -X GET https://discord.com/api/v10/users/@me \
  -H "Authorization: Bearer USER_ACCESS_TOKEN"

```

### Common API Operations

### OAuth2 Token Exchange

 Trade an authorization code for an access token:

```
# filepath: /your/backend/auth.py
import requests

def exchange_code(code, redirect_uri):
    data = {
        'client_id': 'YOUR_CLIENT_ID',
        'client_secret': 'YOUR_CLIENT_SECRET',
        'grant_type': 'authorization_code',
        'code': code,
        'redirect_uri': redirect_uri
    }

    response = requests.post('https://discord.com/api/v10/oauth2/token', data=data)
    return response.json()

```

### User Information

 Retrieve details for the authenticated user:

```
def get_user_info(access_token):
    headers = {'Authorization': f'Bearer {access_token}'}
    response = requests.get('https://discord.com/api/v10/users/@me', headers=headers)
    return response.json()

```

### Using the OpenAPI Specification

 The [Discord OpenAPI Spec](https://github.com/discord/discord-api-spec) can generate a client for your backend language, reducing manual work when calling Discord APIs. [https://openapi-generator.tech/](https://openapi-generator.tech/) is one suitable generator. In python, the flow can look like this:

```
import openapi_client
import os
from pprint import pprint

configuration = openapi_client.Configuration(host = "https://discord.com/api/v10")
configuration.api_key['BotToken'] = 'Bot ' + os.environ["API_KEY"]
with openapi_client.ApiClient(configuration) as api_client:
    api_instance = openapi_client.DefaultApi(api_client)

    request = openapi_client.CreateLobbyRequest()
    request.metadata={'foo':'bar'}
    pprint(api_instance.create_lobby(request))

```

### Best Practices

1. Token Security
  - Do not put bot tokens in client-side code.
  - Store tokens securely

2. Rate Limiting
  - Respect Discord’s [rate limits](https://docs.discord.com/developers/topics/rate-limits)
  - Implement exponential backoff
  - Cache responses when appropriate

3. Error Handling
  - Handle HTTP errors gracefully
  - Add retry handling for temporary failures.
  - Log API errors for debugging
