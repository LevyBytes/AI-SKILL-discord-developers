# Reading Discord API contracts

Open when choosing API authorization, event delivery or version-specific contracts.

These are bundled source references, not live service validation. Distinguish optional from nullable fields, bot from user authorization, Gateway from HTTP delivery, and SDK/runtime variants. Keep permissions, intents, version notes and response/error conditions with the owning operation. Dated changelog entries are historical context. Some examples contain comments, placeholders or fragments of one enclosing program; preserve their syntax and read all linked components before use.

## Operation checks

Check the selected operation, authentication/scopes, intents/permissions, request fields, response shape and source version. Follow example setup, schema footnotes and continuation links. Do not infer missing endpoint paths, undocumented fields or successful execution from a reference lookup.
